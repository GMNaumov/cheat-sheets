# Локальный RAG с Ollama и Qdrant

Пример индексирует PDF-документы из каталога [`docs`](docs/) и отвечает на вопросы через локальную модель. В состав окружения входят Ollama, Qdrant и веб-интерфейс Streamlit.

## Перед началом

Нужны Docker с Compose, подключение к интернету для первой загрузки моделей и PDF-файлы с текстовым слоем.

## Запуск

1. Поместите PDF-файлы с текстовым слоем в каталог `docs`.
2. Соберите и запустите сервисы:

   ```bash
   docker compose up --build -d
   ```

3. Дождитесь запуска `rag-app`: Compose запустит его после перехода Ollama и Qdrant в состояние `healthy`.
4. Откройте `http://localhost:8501`.
5. Нажмите «Проиндексировать PDF», дождитесь загрузки моделей и задайте вопрос.

При первом индексировании Ollama загрузит модель эмбеддингов `nomic-embed-text`, а при первом вопросе — модель `qwen3:4b`. Для загрузки потребуется свободное место на диске.

Фрагменты документов векторизуются пакетами по 32 штуки. При нехватке памяти уменьшите `EMBEDDING_BATCH_SIZE` в `compose.yaml`, например до `8`; при достаточном объёме памяти значение можно увеличить.

Повторная индексация не удаляет коллекцию: новые фрагменты заменяют версии с теми же идентификаторами, а устаревшие точки удаляются только после успешной записи всех новых. Если операция прервётся, прежняя коллекция сохранится, но часть её фрагментов может уже быть обновлена.

Для существующей коллекции нельзя менять модель эмбеддингов на модель с другой размерностью векторов. Для такого перехода задайте новое `COLLECTION_NAME` в `compose.yaml`, проверьте новый индекс и только затем удаляйте старую коллекцию.

## Ограничения

- Каждый вопрос обрабатывается независимо: история диалога не сохраняется и не учитывается в следующих запросах.
- Для ответа выбираются до четырёх ближайших фрагментов без порога релевантности. Приложение может показать источники даже при слабом совпадении, поэтому ответ следует проверять по указанным страницам.
- Индексируются только PDF-файлы в верхнем уровне каталога `docs`; вложенные каталоги не обходятся.

## Проверка состояния

В колонке `STATUS` у Ollama и Qdrant должно быть состояние `healthy`. Если оно остаётся `starting`, повторите `docker compose ps` через несколько секунд. При состоянии `unhealthy` проверьте последние сообщения соответствующего сервиса.

```bash
docker compose ps
docker compose logs --tail=100 ollama qdrant
```

Для непрерывного просмотра логов добавьте `-f` к команде `logs`.

## Остановка

Останавливает контейнеры и сеть проекта. Модели Ollama и индекс Qdrant сохраняются в именованных томах.

```bash
docker compose down
```

## Удаление данных

Следующая команда безвозвратно удалит том Ollama со всеми загруженными моделями и том Qdrant с построенным индексом. Исходные PDF-файлы в каталоге `docs` сохранятся.

```bash
docker compose down --volumes
```
