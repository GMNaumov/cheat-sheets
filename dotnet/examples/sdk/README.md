# .NET SDK через Docker Compose

Локальная среда разработки на .NET 8: SDK работает в контейнере, исходники находятся на хосте, а пакеты NuGet сохраняются в именованном томе.

## Перед началом

Нужны Docker с Compose в режиме Linux-контейнеров, подключение к интернету для загрузки образа и восстановления пакетов, а также свободное место для них. Устанавливать .NET SDK на хост не требуется. Команды ниже подходят для PowerShell и Bash.

В примере сохранён образ `mcr.microsoft.com/dotnet/sdk:8.0` для работы с проектами `net8.0`. Поддержка .NET 8 завершилась 10 ноября 2026 года: эта ветка больше не получает обновления безопасности. Для новых проектов выбирайте поддерживаемую версию по [политике поддержки Microsoft](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core).

Каталог [src](src/README.md) подключается к `/app` с правом записи. Контейнер работает от `root`, поэтому в Linux созданные файлы могут принадлежать `root`. Не используйте эту конфигурацию для production. Порты на хост не публикуются.

## Запуск

Перейдите из корня репозитория в каталог примера:

```bash
cd dotnet/examples/sdk
```

Все последующие команды выполняйте из этого каталога. Проверьте конфигурацию, запустите сервис `sdk` и убедитесь, что SDK доступен:

```bash
docker compose config --quiet
docker compose up -d sdk
docker compose exec sdk dotnet --info
```

В выводе ожидаются SDK `8.0.x` и среда Linux. Команда `tail -f /dev/null` держит контейнер запущенным для выполнения команд через `exec`; приложение автоматически не запускается. Политика `restart: "no"` отключает автоматический перезапуск контейнера.

## Создание и запуск приложения

Если каталог `src/hello-world` ещё не существует, создайте консольное приложение для проверки окружения:

```bash
docker compose exec sdk dotnet new console --name hello-world --output hello-world --framework net8.0
```

Файлы появятся на хосте в `src/hello-world`. Изменяйте их локальным редактором. Локальные проекты и результаты сборки исключены из Git через [правила каталога](src/.gitignore).

Соберите приложение и запустите его в контейнере:

```bash
docker compose exec sdk dotnet build hello-world/hello-world.csproj
docker compose exec sdk dotnet run --project hello-world/hello-world.csproj --no-build
```

**Проверка результата:** сборка завершается без ошибок, а приложение выводит `Hello, World!`.

Для существующего проекта скопируйте его в `src` и замените путь `hello-world/hello-world.csproj` в командах на путь к его файлу проекта относительно `/app`. Проект должен поддерживать Linux и SDK 8; приложения .NET Framework и Windows desktop для этой среды не подходят.

## Остановка

Остановите сервис и удалите контейнер. Исходники на хосте и кэш NuGet в томе сохранятся:

```bash
docker compose down
```

Для повторного запуска используйте команду из раздела «Запуск». Если ранее использовали `dotnet/dotnet-docker/compose.yaml`, перед переходом остановите прежнее окружение и сохраните копию исходников. Перенесите свой `src` в новый каталог примера; из-за смены каталога Compose создаст новый том кэша, и пакеты восстановятся заново. Старый том автоматически не удаляется.

## Удаление кэша

Следующая команда безвозвратно удалит именованный том с пакетами NuGet этого примера. При следующей сборке пакеты потребуется скачать заново. Исходники в `src` останутся на хосте:

```bash
docker compose down --volumes
```
